FreeRTOS 智能窗户温控系统

STM32F103 + FreeRTOS + C++ 上位机，从底层驱动到 PC 控制全链路闭环，整合 7 大外设模块实现手自一体温控

STM32F103C8T6FreeRTOSDHT22I²C OLEDHC-08 蓝牙Flash 存储IWDGC++ 上位机
1

项目概述

独立完成基于 STM32F103C8T6 与 FreeRTOS 实时操作系统的智能窗户温控系统。下位机整合 DHT22 单总线传感器、I²C OLED 显示、PWM 舵机控制、ADC 模拟采集、HC-08 蓝牙通信、Flash 掉电存储、IWDG 独立看门狗七大模块，实现 4°C 滞回自动温控算法与手机蓝牙 AT 指令双模控制。配套 C++ 上位机通过 HC-08 虚拟串口实现 PC 端远程操控，完成从底层驱动到 PC 控制的全链路闭环。

核心功能

  • DHT22 单总线温湿度采集，DWT 硬件周期计数器 μs 级脉宽测量，CRC 8-bit 校验 + 3 次自动重试
  • 4°C 滞回自动温控算法：温度 >32°C 自动开窗，<28°C 自动关窗，4°C 区间防抖动
  • I²C OLED 四行实时显示：ADC 电压 / 温度 / 湿度 / 模式+窗户状态
  • HC-08 蓝牙 9600bps 透传：8 条 AT 指令支持手机/PC 双模控制，手动/自动模式随时切换
  • Flash 双页磨损均衡：掉电不丢失温湿度极值与舵机开关次数，上电自动恢复
  • 双重容错：IWDG 硬件看门狗（4s 超时复位）+ 软件层 DHT22 连续失败主动复位

核心技术实现

3.1 FreeRTOS 双任务架构

系统划分两大 FreeRTOS 任务，通过 xTaskNotifyGive / ulTaskNotifyTake 实现单向通知（零拷贝）：

任务优先级栈大小周期职能
WDG (看门狗监控)3 (最高)256B5s 超时等通知喂狗 / 超时复位 / 错误计数
Main (主任务)1512B~2.2s传感器采集 + 温控 + OLED + 蓝牙指令

主任务循环流程

流程 ① ADC 采集 adc_v = ADC_GetVoltage() ② DHT22 采集 err = DHT22_ReadRetry(&temp, &hum, 3) ③ 看门狗喂狗 WDG_TaskAlive() / WDG_ReportDHTError() ④ 自动温控判断 temp > 32°C 开窗 / temp < 28°C 关窗 (4°C 滞回) ⑤ OLED 四行刷新 ADC / Temp / Humi / 模式+窗户状态 ⑥ 蓝牙指令处理 HC08_GetLine() 环形缓冲取一行 → ProcessCommand() ⑦ vTaskDelay 2s ⑧ 回到 ①
任务间通信xTaskNotifyGive / ulTaskNotifyTake（单向通知，零拷贝）
串口接收USART1 中断 → 环形缓冲区（256B）→ 主循环轮询取出
Flash 写入主循环直接调用 Flash API（非中断上下文，安全）

3.4 Flash 双页磨损均衡 & 双重容错

Flash 双页交替写入

页 A (0x0800F800) ↔ 页 B (0x0800FC00)

写入序号 +1 → 擦除对页 → 写入对页 → 切换活动页
加载读两页 → 比较序号 → 加载较新的 → 恢复 RAM
寿命10 万次/页 × 2 页 = 20 万次有效写入

双重容错机制

软件层DHT22 连续 3 次失败 → NVIC_SystemReset() 主动复位（~6s 响应）
硬件层IWDG 4 秒超时 → 硬件强制复位（CPU 死锁/停振也能恢复）

开发难点 & 解决方案

难点 1：DHT22 单总线时序极易被中断打断

现象：DHT22 读取成功率仅 ~70%，频繁出现 CRC 校验失败或无应答

根因分析：单总线协议的 μs 级时序被 FreeRTOS 任务切换或 SysTick 中断打断，导致 DWT 脉宽测量出现偏差。40 位数据中任意 1 位误判即导致 CRC 校验失败。

解决方案：

  • 读取期间临时关闭全局中断（__disable_irq），保证 40 位数据的时序完整性（关中断窗口 <5ms）
  • 利用 Cortex-M3 内核 DWT 硬件周期计数器实现 μs 级脉宽测量，无需额外定时器资源
  • CRC 8-bit 校验失败 + 无应答 → 自动重试最多 3 次（仅重试这两种错误，不浪费重试次数）
  • 连续 3 轮全部失败 → 触发软件复位（配合 IWDG 硬件兜底）

效果：读取成功率从 ~70% 提升至 99.5%+

难点 2：Flash 频繁擦写导致寿命瓶颈

现象：系统需要保存温湿度极值和舵机开关次数，若每次变化都擦写同一页，STM32F103 内部 Flash 仅 ~10K 次寿命，频繁写入数天即耗尽。

解决方案：

  • 双页交替：划分 Flash 第 62/63 页（各 1KB），交替写入。每次写入时序号 +1，擦除对页后写入，然后切换活动页
  • 增量写入：仅在温湿度破极值或舵机动作时才写入，而非定时写入，大幅减少擦写次数
  • 上电恢复：启动时读取两页序号，加载较新的数据并恢复 RAM 中的极值与计数器

效果：有效写入寿命从 ~10K 次提升至 20 万次，预期使用寿命从数天延长至数年

难点 3：蓝牙透传数据粘连与断帧

现象：HC-08 连续接收数据时，AT 指令帧边界混乱，出现半帧/粘帧，导致指令解析错误

解决方案：

  • USART1 中断接收 → 环形缓冲区（256B）异步写入，不丢字节
  • 主循环 HC08_GetLine() 非阻塞取行：以 \n 为界提取完整指令行，无 \n 则全部取出（兼容各种终端）
  • 发送端 HC08_SendString() 严格等待 TXE（TDR 空）+ TC（最后一字节完全移出），确保发送完整

难点 4：DHT22 + OLED + 蓝牙三模块协同稳定性

现象：OLED 刷新时 DHT22 读取偶发失败，蓝牙发送时 OLED 出现短暂花屏

解决方案：主任务循环中严格串行化外设操作（ADC→DHT22→WDG→温控→OLED→蓝牙→Delay），每次仅操作一个外设，避免资源竞争。DHT22 读取期间关中断保证时序，OLED 和蓝牙操作在开中断环境下执行。

📄 DHT22.c — DWT 微秒级脉宽测量 + CRC 重试
C /* DHT22 单总线读取：DWT μs脉宽测量 + 3次CRC重试 */ #define DHT22_RETRY_MAX 3 uint8_t DHT22_Read(float *temp, float *humi) { uint8_t buf[5] = {0}; for (uint8_t retry = 0; retry < DHT22_RETRY_MAX; retry++) { __disable_irq(); // 关中断保证时序 DHT22_StartSignal(); // 主机起始信号 if (DHT22_ReadPulses(buf) == 0) { // 读40位脉宽 __enable_irq(); continue; // 无应答，重试 } __enable_irq(); if (DHT22_CRC8(buf, 4) == buf[4]) { // CRC校验通过 *humi = (buf[0]<<8 | buf[1]) * 0.1f; *temp = (buf[2]<<8 | buf[3]) * 0.1f; return 1; // 成功 } vTaskDelay(pdMS_TO_TICKS(20)); // 重试间隔20ms } return 0; // 连续失败 } /* DWT硬件周期计数器: 无需定时器，误差<1μs */ static uint8_t DHT22_ReadPulses(uint8_t *buf) { uint32_t start = DWT->CYCCNT; for (uint8_t i = 0; i < 40; i++) { while (!(GPIOB->IDR & DHT22_PIN)); // 等上升沿 uint32_t t = DWT->CYCCNT - start; while (GPIOB->IDR & DHT22_PIN); // 等下降沿 buf[i/8] <<= 1; if (t > 50) buf[i/8] |= 1; // >50μs为1, <50μs为0 } return 1; }

C /* Flash 双页磨损均衡：页A ↔ 页B 交替写入 */ #define FLASH_PAGE_A 0x0800F800 // 第62页 #define FLASH_PAGE_B 0x0800FC00 // 第63页 static uint32_t g_active_page = FLASH_PAGE_A; static uint32_t g_write_seq = 0; void Flash_SaveHistory(History_t *data) { uint32_t target_page = (g_active_page == FLASH_PAGE_A) ? FLASH_PAGE_B : FLASH_PAGE_A; data->seq = ++g_write_seq; // 序号递增 FLASH_ErasePage(target_page); // 擦除对页 FLASH_ProgramPage(target_page, data); // 写入对页 g_active_page = target_page; // 切换活动页 } void Flash_LoadHistory(History_t *data) { History_t pageA, pageB; FLASH_ReadPage(FLASH_PAGE_A, &pageA); FLASH_ReadPage(FLASH_PAGE_B, &pageB); // 加载序号较大的（较新的）数据 if (pageA.seq >= pageB.seq) { memcpy(data, &pageA, sizeof(History_t)); g_active_page = FLASH_PAGE_A; } else { memcpy(data, &pageB, sizeof(History_t)); g_active_page = FLASH_PAGE_B; } g_write_seq = data->seq; }

项目总结 & 个人收获

项目成果

  • 双任务架构稳定运行，上电 3 秒内完成 7 个硬件模块初始化与调度器启动
  • DHT22 采集成功率 99.5%+，4°C 滞回温控无抖动
  • Flash 双页磨损均衡 + 掉电保护，预期使用寿命数年
  • 双重容错机制保障 7×24 小时无人值守运行
  • C++ 上位机单 exe <100KB，无第三方依赖，COM 口即插即用

个人收获

  • 全模块自研驱动：7 个外设驱动均为独立编写（无 HAL 库依赖），深入理解了 GPIO/I²C/USART/ADC/PWM/Flash 的寄存器级操作
  • FreeRTOS 实战：掌握了任务划分、优先级设计、xTaskNotify 任务间通信、关中断保护临界区等核心技能
  • 系统容错思维：从 DHT22 重试 → 软件复位 → IWDG 硬件兜底，建立了"分层容错"的设计理念
  • 数据持久化：学会了 Flash 磨损均衡与掉电保护的设计思路，理解了嵌入式存储与 PC 存储的本质区别
  • 全链路闭环：从底层传感器驱动 → 蓝牙透传 → C++ PC 上位机，体验了完整的嵌入式 IoT 数据链路

后续改进方向

  • 引入 FatFS + SPI Flash 扩展存储，支持长时间历史数据记录与 CSV 导出
  • 增加 ESP8266 WiFi 模块，实现云端数据上报与远程监控（MQTT 协议）
  • 移植到 STM32F407 平台，利用 FPU 实现更复杂的温控 PID 算法
