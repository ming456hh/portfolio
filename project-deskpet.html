智能桌面小狗

基于 STM32F103 的事件驱动状态机，兼容离线语音与蓝牙双通道指令，驱动多路舵机完成动作序列，指令响应 <300ms

STM32F103C8T6状态机语音识别蓝牙舵机控制
1

项目背景与需求

本项目来自机器人创新实验室（2024.05-2024.06），是第一个独立完成的嵌入式项目。目标是制作一个桌面级的语音/蓝牙双控宠物机器人，通过多路舵机实现丰富的动作表达。

功能需求

  • 离线语音指令识别 + 蓝牙串口遥控，双通道指令仲裁
  • 多路舵机（头、尾、四肢）协同动作，支持多套预设动作序列
  • 非阻塞定时器控制动作时序，避免阻塞式 delay 影响响应
  • 指令响应耗时 <300ms

核心实现思路与技术亮点

事件驱动状态机

系统核心是一个有限状态机 (FSM)，将所有外部指令（语音/蓝牙/按键）抽象为统一的事件类型，由状态机统一仲裁，避免多通道指令冲突。

  • 定义 5 个状态：IDLE / LISTENING / ACTING / PAUSED / ERROR
  • 语音和蓝牙指令统一转换为内部事件枚举，状态机查表执行动作
  • 指令优先级：急停 > 语音 > 蓝牙（按键仲裁）

非阻塞动作控制系统

定时器驱动使用 SysTick 定时器实现毫秒级非阻塞延时，舵机动作序列在定时器中断中逐帧推进。
动作序列预定义多套动作帧表（坐下/握手/摇尾巴/转圈），每帧包含 4 个舵机目标角度 + 持续时长。
<300ms 响应状态机主循环不阻塞，指令到达→解析→动作触发全链路在 300ms 内完成。

遇到的难点与解决方案

难点 1：舵机启动瞬间电压跌落导致 MCU 复位

现象：多路舵机同时开始动作时，系统偶发复位

分析：4 个 SG90 同时启动，总瞬态电流 >2A，USB 5V 供电无法满足，电压跌落至 MCU 欠压阈值。

解决：

  • 硬件层面：舵机电源并联 1000μF 电解电容 + 0.1μF 陶瓷电容，独立于 MCU 供电走线
  • 软件层面：舵机启动时序错峰 50ms，避免同时突增电流
  • 最终彻底解决复位问题，系统运行稳定

难点 2：语音识别误触发与蓝牙指令冲突

现象：环境噪音导致语音模块误识别，与蓝牙指令同时到达时动作混乱

解决：语音模块配置关键词唤醒 + 置信度阈值过滤；状态机中定义指令优先级（正在执行动作时忽略新指令，除非是急停）。双通道指令加入时间戳，100ms 内只接收一条。

关键代码片段

📄 fsm.c — 事件驱动状态机
C /* 事件驱动状态机：统一仲裁语音/蓝牙/按键指令 */ typedef enum { STATE_IDLE, STATE_LISTEN, STATE_ACT, STATE_PAUSE, STATE_ERR } FSM_State_t; typedef enum { EVT_VOICE_CMD, EVT_BT_CMD, EVT_KEY, EVT_ACTION_DONE, EVT_ESTOP, EVT_ERROR, EVT_NONE } FSM_Event_t; typedef struct { uint8_t servo_id; // 舵机编号 uint16_t target_pwm; // 目标 PWM (500~2500) uint16_t duration_ms; // 持续时长 } ActionFrame_t; typedef struct { ActionFrame_t *frames; uint8_t frame_count; uint8_t current_frame; } ActionSeq_t; FSM_State_t FSM_Dispatch(FSM_Event_t event, uint8_t cmd_id) { static FSM_State_t state = STATE_IDLE; static ActionSeq_t *active_seq = NULL; switch (state) { case STATE_IDLE: if (event == EVT_VOICE_CMD || event == EVT_BT_CMD) { active_seq = Action_Lookup(cmd_id); if (active_seq) { state = STATE_ACT; Action_Start(active_seq); } } break; case STATE_ACT: if (event == EVT_ACTION_DONE) { state = STATE_IDLE; // 动作完成，回 idle } else if (event == EVT_ESTOP) { Action_Abort(active_seq); state = STATE_IDLE; // 急停优先 } // 正在执行时忽略新指令（防止冲突） break; } return state; }

C /* 非阻塞舵机控制：SysTick 定时器驱动帧推进 */ void Servo_ActionTick(void) // 在 SysTick ISR 中调用 { static uint16_t tick_ms = 0; tick_ms++; for (uint8_t i = 0; i < SERVO_COUNT; i++) { ServoChannel_t *ch = &servo_channels[i]; if (!ch->active) continue; // 当前帧持续时间到达，推进下一帧 if (tick_ms - ch->frame_start >= ch->frame_duration) { ch->current_frame++; if (ch->current_frame >= ch->total_frames) { ch->active = 0; // 序列完成 FSM_NotifyEvent(EVT_ACTION_DONE); continue; } ch->frame_start = tick_ms; ch->frame_duration = ch->sequence[ch->current_frame].duration_ms; Servo_SetPWM(i, ch->sequence[ch->current_frame].target_pwm); } } }

项目总结与个人收获

项目成果

  • 实现语音 + 蓝牙双通道控制，指令响应 <300ms
  • 非阻塞状态机 + 定时器驱动舵机动作序列，动作流畅无卡顿
  • 解决舵机启动电压跌落问题，系统运行稳定可靠

个人收获

  • 第一个独立完成的嵌入式项目，建立了从需求到成品的完整开发流程认知
  • 掌握事件驱动状态机的设计方法，学会多通道指令仲裁与优先级管理
  • 学会了处理电源噪声和系统稳定性问题，理解了硬件与软件的协同设计

后续改进方向

  • 引入 FreeRTOS 替代裸机状态机，提升多任务处理能力
  • 增加 MPU6050 检测倾翻自动起身
